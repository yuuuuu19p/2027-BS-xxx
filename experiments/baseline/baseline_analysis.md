# Baseline 问题分析报告

> 对应检查项：Baseline 问题分析。本报告基于 2026-10-07 实际运行结果（`results/logs/baseline_run1.jsonl`，50 题全量）。

## 一、运行环境与配置

- 硬件：CPU（型号待补录） / GPU：NVIDIA GeForce RTX 4060 Laptop GPU（8 GB 显存，CUDA 加速）
- 模型与量化：qwen2.5:1.5b-instruct-q4_K_M（Q4_K_M / INT4，GGUF，1.1 GB）
- 引擎：Ollama 0.40.0（Windows，安装于 D:\Ollama，模型目录 D:\OllamaModels）
- 问题集规模：50 题（教务 / 图书馆 / 后勤 / 网络 / 财务 / 学工 / 餐饮 / 体育 / 就业 / 校园安全，各 5 题）
- 推理参数：temperature=0.2，max_tokens=512，system_prompt=校园问答助手中文提示词

## 二、问题现象

| # | 现象 | 具体表现 / 例子 | 严重程度 |
|---|---|---|---|
| 1 | 幻觉：编造具体数值 | "图书馆周末 8:00–17:00"、"食堂 6:00–22:00"、"体育馆 8:00–17:00" —— 均为模型自编，非本校实际规定 | 高 |
| 2 | 校园专属信息答错 | "校园报警电话是多少？" → 答 "110"（非本校安保值班电话口径）；"就业指导中心" → 答 "教务处或学生处"（非确切地址） | 高 |
| 3 | 回答通用化、回避细节 | "网络密码找回"、"学费缴纳方式"等回答为通用流程复读，无本校入口/流程 | 中 |
| 4 | 过短回答 | 1/50 题回答 <10 字（校园报警电话） | 低 |
| 5 | 性能与资源 | 热态 avg 3.07 s/题（中位 3.05 s）、37.4 tok/s、ttft 211 ms；冷启动首次请求约 55 s（模型加载）；GPU 显存峰值 3.35 GB | 低（RTX 4060 上充裕） |

## 三、原因分析

1. **无检索注入**（核心）：Baseline 为 no-RAG，模型只能依赖内部参数知识；其训练语料不包含本校政策、开放时间、部门电话等专属信息，遇到具体数值时只能"合理猜测"，即幻觉。
2. **模型容量有限**：1.5B 参数在指令遵循与知识容量上较弱，倾向输出通用模板式回答，且难以表达"我不知道"。
3. **问题属性**：标准问题集均为"本校专属"信息型问题（电话、时间、流程、地点），恰好命中模型知识盲区，放大了上述两个问题。
4. **冷启动**：模型首次加载耗时约 55 s，属于部署侧正常现象，可通过常驻/预加载缓解，不影响稳态指标。

## 四、对策与后续实验映射

| 现象 | 对策 | 对应实验 |
|---|---|---|
| 幻觉 / 编造具体数值 | 引入 RAG：知识库检索注入校园上下文，回答须基于检索内容 | EXP-002 / `exp01_rag_link` |
| 校园专属信息答错 | 提高知识库覆盖率 + 优化检索（Top-k、chunk size） | EXP-006 / EXP-007 |
| 回答通用化 | 提示词约束"仅依据给定资料回答"+ RAG 上下文 | EXP-002 |
| 冷启动 / 资源占用 | 常驻预加载；INT4 vs INT8、更小/更大模型对比 | EXP-003 / EXP-004 |
| 边缘 CPU 场景 | 另行在 CPU 上测速（本机 GPU 场景不代表 CPU 边缘设备） | EXP-003 / EXP-004 |

## 五、结论

Baseline（no-RAG）在 50 题标准问题集上的表现说明：**无检索时，本地小模型对校园信息型问题的回答不可用**——虽然流畅、中文、结构完整，但大量幻觉与错误，无法直接面向用户。同时量化了资源基线（RTX 4060 上 3.1 s/题、37 tok/s、3.35 GB 显存），证明 1.5B Q4 模型在消费级 GPU 上性能充裕、资源占用低。后续 EXP-002 起引入 RAG 后，将用 RAGAS（faithfulness / answer_relevancy）与人工抽检对比质量提升，并研究 Top-k、chunk size 的影响。
