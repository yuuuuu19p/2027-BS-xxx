# 技术路线

> 初稿，随实验推进更新。本目录为题目冻结区，仅存 3 份文件。

## 一、总体思路

校园服务资料采集 → 清洗与切分（chunk）→ 嵌入向量化 → 向量库（FAISS 等）→ 用户提问（Top-k 检索）→ 检索结果 + 提示词组装 → 本地 LLM 生成回答（INT8/INT4 量化，CPU/消费级 GPU）→ 回答质量评估（RAGAS / 标准问题集）。

## 二、技术选型（候选，待实验确认）

| 环节 | 候选方案 | 说明 |
|---|---|---|
| 本地 LLM | Qwen 等系列小模型（1.5B / 7B 量级） | 至少对比两种模型大小 |
| 量化方案 | INT8 / INT4（GGUF、AWQ、GPTQ 等） | 至少对比两种量化方案 |
| 向量库 | FAISS / Chroma 等 | 待定 |
| 嵌入模型 | BGE 等中文 embedding | 待定 |
| 推理框架 | llama.cpp / Ollama / vLLM 等 | 待定 |
| 评测 | RAGAS + 标准问题集 | 已定方向 |

## 三、关键流程与步骤

1. 建立校园服务知识库与标准问题集；
2. 完成本地 LLM + RAG 完整链路；
3. 量化部署与资源测试（CPU/消费级 GPU）；
4. 对比实验：模型大小 × 量化方案；
5. 检索参数研究：Top-k、chunk size 至少一种；
6. RAG 前后回答质量对比与评测。

## 四、备选方案与风险

| 风险 | 影响 | 备选方案 |
|---|---|---|
| CPU 推理过慢 | 时延超标、体验差 | 更小模型 / 更低量化位宽 / 回答缓存 |
| 检索质量差 | 回答失真、幻觉 | 调 Top-k、chunk size；更换嵌入模型 |
| 显存不足（OOM） | 无法部署 | 降位宽、降上下文长度、分批加载 |

## 五、验证方式

- 回答质量：标准问题集上 RAGAS 指标（faithfulness、answer relevancy 等）与人工抽检；
- 资源与性能：显存、内存、推理时延、吞吐量。
